关于「能不能直接搬网页版的逻辑」——正面回答

整套搬进来：做不到。网页版是 React + 编译后的 CSS + 一整套状态库，必须跑在浏览器引擎里，没法作为 Swift 组件复用。能整套搬的方式只有「整页 WebView」（路线 A），那条路的代价（后台通知交接）我们已经试过一轮。

但可以搬三样东西，这轮的「不适配」大多是因为我只搬了两样：

1. 数据模型（已搬）：行类型、bootstrap、fileChanges 这些协议字段都对齐了官方。
2. 视觉规范（已搬）：图标、颜色、折叠交互都对。
3. 展示逻辑（之前是我自己发明的，这是 bug 主因）：接下来凡是有现成官方行为的视图（审查 diff、打开文件、思考折叠规则、文件卡片），一律照官方的状态机写，不再自创。

再补一个务实的混合招：像代码 diff、复杂表格这类「自己写永远差点意思」的视图，用本地生成的 HTML 塞进 WKWebView 渲染（官方 Kimi 也是这么干公式渲染的）——视觉对齐网页，一次写好不碎。上面侧边栏里的 diff 在 App 里就打算这么做。

如果你之后觉得原生这条路还是太累，路线 A（整页 WebView + 后台监控交接）的包一直在仓库里，随时能切回去。

  • 试试：点文件行的「审查」→ 右侧滑出侧边栏，审查页签是 diff；点「文件」页签是打开效果；✕ 或点左边暗处关闭。聊天里的 ✏️ 写入行保持内联展开（你确认过的那个效果）。
